# 从图标库生成项目内 PNG

需要新增图标、选择图标来源或建立转换流程时读取。不要求项目启用 Expand 或图集。

## 目标

从合适的开源图标库获取所需图标，按项目参数生成 PNG，放入项目已有资源目录。运行时使用本地 PNG，不依赖图标服务、图标库包或 Skill 目录。

来源可以是图标库包、官方仓库、Iconify 等集合或已取得的源文件。不同图标可来自不同集合，但应符合项目视觉需求；不默认限定 Phosphor、单色或某种线条风格。

## 来源与生成参数

先沿用已有图标风格和资源规范。没有现成规范时，根据实际任务确定来源、具体图标及下面真正需要的参数：

- 输出名称、尺寸或需要的多个分辨率；尺寸是 PNG 像素，不自动等同于引擎逻辑尺寸。
- 单色、多色或渐变；是否保留原色，是否需要透明背景与留白。
- 单色图标采用生成时着色还是运行时染色。多色图标不能默认转换为白色掩码。
- 图标的描边、填充、轮廓版本或主题变体。

优先通过官方来源或已安装的集合获取，避免用网页截图代替源图标。记录集合、图标名、版本或源地址，以及来源要求保留的许可或署名信息。已明确选定的来源无需反复询问。

## 可重复的生成流程

在目标项目留下能重建实际输出的来源说明或配置和生成命令。依赖可锁定的包版本、源文件或提交版本，避免只记录一个可能变化的在线地址。

已有可靠脚本时扩展它，不另起一套。需要新脚本时，按目标项目环境选用合适的栅格化工具。例如 JS 项目可使用 Iconify 数据和 Sharp，其他项目可采用已有 SVG/PNG 转换工具。

一个可选配置示意如下；字段不是 Skill 或图标工具的内置语法，采用它时必须实现对应解析：

```json
{
  "defaults": { "size": 128, "background": "transparent" },
  "icons": {
    "close": {
      "source": "collection:icon-name",
      "appearance": "monochrome",
      "color": "#ffffff"
    },
    "achievement": {
      "source": "local:art/achievement.svg",
      "size": 256,
      "appearance": "original"
    }
  }
}
```

实际格式与现有项目保持一致，不为使用本示意而迁移已有配置。

转换时保留 SVG 的 viewBox、画布比例和必要的渐变、裁剪、透明度与描边。`currentColor` 可以按所选单色参数解析；不要对多色 SVG 全局替换 fill/stroke，也不要为了统一尺寸裁掉有意义的边缘。先验证所有输入和目标路径，再改写生成文件。

生成脚本只管理自身明确生成的文件。清理时使用生成清单等所有权信息，保留手工图片；遇到已被手工修改的历史输出，不静默删除或覆盖。写入和清理均限定在项目选定的生成资源目录。

输出 PNG 的提交与构建策略沿用项目约定：

- 将 PNG 提交到仓库时，应能检查配置与实际输出是否一致，新的检出不依赖临时生成缓存。
- 在构建前生成时，将生成步骤接入实际构建链路，并确保离线或干净环境具备所需源文件与依赖。
- 不为仅新增少量图标强制建立自动下载服务，也不默认让开发服务器每次启动都重新生成。

## 接入与验证

通过项目现有的图片加载或导入方式使用 PNG。若项目已接入透明图集，生成的 PNG 和手工碎图走同一资源流程，不为图标单独建立业务加载 API。

检查实际输出尺寸、透明度和内容完整性，查看小尺寸下的清晰度及多色保留情况。在引擎内验证显示比例、染色策略和状态切换。检查生产运行时不向图标服务发请求。

对于脚本改动，验证相同输入重复运行结果稳定，缺失图标给出可定位错误，移除配置项不会删除无关素材。只检查输出文件存在，不足以确认颜色和裁剪正确。

完成时留下本次图标来源、生成参数、输出路径、重建命令以及项目需要的来源声明。
