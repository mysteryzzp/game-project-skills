# 多分辨率下的 UI 布局与游戏视野

先确定玩家在各目标设备上需要看清哪些控件、看到多大范围的场景。可以为同一画面的界面和世界相机选择不同策略。

- 菜单、弹窗或有固定构图的界面通常需要保留完整设计区域。Expand 适合在保留该区域的同时，把屏幕比例差异带来的额外空间用于布局。
- 有大战场和移动相机的游戏，如果希望大屏提供更开阔的视野，可以小屏上可辨认的角色或地块大小为基准。在二维地图中，一种做法是让每格占用大致稳定的逻辑显示尺寸，可用窗口越大，相机就能容纳更多行列。HUD 可独立调整字号、按钮大小和边距。若将整个世界和 HUD 一起等比放大，宽高比相同的大屏可能只把原来的战场画得更大。
- 有些玩法需要各设备看到相近的区域，例如固定构图的解谜关卡，或要求统一视野的竞技模式。可以保留指定的世界范围，或为相机设置视野上限。是否扩展、沿哪个方向扩展以及扩展多少，由关卡和玩法决定。

判断可用空间时，以项目的逻辑窗口或引擎视口为准。同一窗口提高渲染像素密度通常只需提高清晰度。

## 选择 Expand 时的几何关系

设参考设计尺寸为 `Dw × Dh`，可用显示区域为 `W × H`：

```text
s  = min(W / Dw, H / Dh)
Vw = W / s
Vh = H / s
```

- `s` 为统一等比缩放率，不能横纵分别缩放。
- `Vw × Vh` 为实际逻辑视口，宽高比与可用显示区域一致。
- `Vw >= Dw`、`Vh >= Dh`，完整保留参考设计区域，不靠裁切实现适配。
- 相对设计比例更长的区域扩展纵向逻辑范围，更宽的区域扩展横向逻辑范围。
- UI 的贴边、居中和拉伸依据实际逻辑视口，不固定依据设计矩形。

参考设计尺寸由项目已有美术或需求确定，没有通用的 `720×1280` 默认值。开发平台、引擎分辨率设置和设计尺寸是不同概念。

## 接入决策

先检查引擎的参考分辨率、UI 容器、相机和视口设置。若 UI 与世界采用不同策略，可用 UI 布局容器管理控件缩放与锚点，由相机管理世界的可见范围和移动边界。优先复用引擎已有机制。

如需自定义实现，集中处理窗口尺寸变化，分别更新受影响的 UI 布局和相机。UI 命中检测沿用布局坐标，地图点选与拖动使用当前相机的屏幕到世界坐标变换。根节点分层只是实现选项，不要求所有引擎采用相同的节点名称或树结构。

引擎可能采用底部原点、中心原点或不同轴方向。保留其常规坐标系，用引擎自带变换或局部布局处理原点，不为了复刻案例而全局转换坐标。

选用 Expand 时，核对原生模式的实际行为。

- 固定宽度可能在某些比例下缩小纵向范围，不能据其名称认定为 Expand。
- 等比缩放后留黑边、裁切内容、只缩放 UI 字体，也不等于扩展逻辑视口。
- 若原生设置只完成缩放而不扩展布局范围，补上缺失部分即可。

## 项目参数和边界

根据项目需要确定这些参数，不为一次简单适配强制增加全套配置：

| 决策 | 对实现的影响 |
| --- | --- |
| 参考设计尺寸和允许方向 | 决定缩放基准，横竖屏是否共用同一基准 |
| 适配窗口还是内部显示区域 | 分屏、嵌入式画布和编辑器预览应使用真实容器尺寸 |
| 安全区域 | 背景可铺满显示区域，关键交互可约束到安全区域 |
| 世界相机的可见范围与移动边界 | 按玩法决定是否随窗口扩展、是否限制最大视野，并按实际可见范围处理地图边缘 |
| 极宽屏布局 | 可以重排或限制局部内容宽度，采用 Expand 的界面保留其视口关系 |

安全区域通常是在已计算视口中增加布局约束；若项目选择对安全区域本身做 Expand，明确 `W/H` 的边界并保持背景与交互坐标一致。不要重复扣除安全边距。

## 尺寸、输入与生命周期

- Web 的 `W/H` 通常取 CSS 像素；原生引擎使用其视口 API 所定义的单位。确认底层单位，不能机械套用 Web 的 CSS/DPR 说法。
- 渲染像素密度用于清晰度和性能，不应再乘入已经完成的布局缩放。
- 子节点继承整体变换后，不重复乘缩放率。输入坐标交给引擎坐标转换能力，避免界面与点击区域错位。
- 尺寸、方向或容器变化时重新计算；初始化或最小化期间 `W/H` 为零时延后更新，避免除零。
- 布局变化只更新位置和尺寸，不应重置业务状态、重复注册监听或重播入场动画。
- 普通图片采用 fill、contain、cover 或九宫格属于项目的图片显示策略，本模块不统一规定。

## 验证

从目标设备中选取代表性的小屏和大屏，覆盖项目支持的屏幕比例和方向。

1. 采用 Expand 的界面满足上述几何关系，参考设计区域完整可见。
2. 顶部和底部控件跟随相应边界，居中内容位于指定区域中心；扩展区域按所选布局使用。
3. 关键内容和交互区域可见，点击、拖动与视觉位置一致。
4. 连续 resize、方向变化及高像素密度下行为稳定，业务状态不被适配过程重置。

有世界相机时，在同一处远离地图边缘的位置，对比宽高比相同、可用逻辑尺寸不同的小窗和大窗。若目标是大屏多看战场，用可见地块数或地标确认大窗显示了额外区域，同时检查 HUD 的可读性和操作尺寸。若玩法限定视野，则核对两端的可见范围是否符合约定。移动相机到地图边缘，再验证边界与点选位置。

数学检查不能替代引擎内的布局与输入验证。优先复用已有预览和检查入口，选择足以验证当前变化的检查范围。

## Expand 数学示例

仅用于说明几何关系，设计尺寸 `720×1280` 不是默认要求：

| 显示区域 | 缩放率 | 逻辑视口 |
| --- | --- | --- |
| `720×1280` | `1` | `720×1280` |
| `720×1600` | `1` | `720×1600` |
| `1440×900` | `0.703125` | `2048×1280` |

这些结果应与引擎最终坐标和布局范围一致，而不仅仅是单独的计算函数返回值。
