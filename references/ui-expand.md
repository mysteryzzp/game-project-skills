# Expand 多分辨率适配

建立或调整 UI 适配时读取。本模块定义跨引擎的几何行为；节点结构、布局系统和调用 API 由目标引擎决定。

## 行为目标

设参考设计尺寸为 `Dw × Dh`，可用显示区域为 `W × H`：

```text
s  = min(W / Dw, H / Dh)
Vw = W / s
Vh = H / s
```

- `s` 为统一等比缩放率，不能横纵分别缩放。
- `Vw × Vh` 为实际逻辑视口，宽高比与可用显示区域一致。
- `Vw >= Dw`、`Vh >= Dh`，完整保留参考设计区域，不靠裁切实现适配。
- 相对设计比例更长的区域扩展纵向逻辑范围，更宽的区域扩展横向逻辑范围。
- UI 的贴边、居中和拉伸依据实际逻辑视口，不固定依据设计矩形。

参考设计尺寸由项目已有美术或需求确定，没有通用的 `720×1280` 默认值。开发平台、引擎分辨率设置和设计尺寸是不同概念。

## 接入决策

先检查引擎的参考分辨率、Canvas/Camera、视口和容器布局能力。引擎可能已能完成全部适配；能满足目标时直接配置并验证，不再叠加自定义缩放根节点。

如需自定义实现，将视口计算和整体缩放放在一个公共入口。布局、坐标转换、命中检测共享同一套坐标关系。根节点分层只是实现选项，不要求所有引擎采用相同的节点名称或树结构。

引擎可能采用底部原点、中心原点或不同轴方向。保留其常规坐标系，用引擎自带变换或局部布局处理原点，不为了复刻案例而全局转换坐标。

注意原生模式的实质行为：

- 固定宽度可能在某些比例下缩小纵向范围，不能据其名称认定为 Expand。
- 等比缩放后留黑边、裁切内容、只缩放 UI 字体，也不等于扩展逻辑视口。
- 若原生设置只完成缩放而不扩展布局范围，补上缺失部分即可。

## 项目参数和边界

根据项目需要确定这些参数，不为一次简单适配强制增加全套配置：

| 决策 | 对实现的影响 |
| --- | --- |
| 参考设计尺寸和允许方向 | 决定缩放基准，横竖屏是否共用同一基准 |
| 适配窗口还是内部显示区域 | 分屏、嵌入式画布和编辑器预览应使用真实容器尺寸 |
| 安全区域 | 背景可铺满显示区域，关键交互可约束到安全区域 |
| UI 与世界场景的关系 | 不默认要求游戏世界或相机使用同一适配方式 |
| 极宽屏布局 | 可以重排或限制局部内容宽度，同时保持 Expand 的视口关系 |

安全区域通常是在已计算视口中增加布局约束；若项目选择对安全区域本身做 Expand，明确 `W/H` 的边界并保持背景与交互坐标一致。不要重复扣除安全边距。

## 尺寸、输入与生命周期

- Web 的 `W/H` 通常取 CSS 像素；原生引擎使用其视口 API 所定义的单位。确认底层单位，不能机械套用 Web 的 CSS/DPR 说法。
- 渲染像素密度用于清晰度和性能，不应再乘入已经完成的布局缩放。
- 子节点继承整体变换后，不重复乘缩放率。输入坐标交给引擎坐标转换能力，避免界面与点击区域错位。
- 尺寸、方向或容器变化时重新计算；初始化或最小化期间 `W/H` 为零时延后更新，避免除零。
- 布局变化只更新位置和尺寸，不应重置业务状态、重复注册监听或重播入场动画。
- 普通图片采用 fill、contain、cover 或九宫格属于项目的图片显示策略，本模块不统一规定。

## 验证

用项目目标设备选择代表性的同设计比例、长屏、宽屏和允许的横屏尺寸，检查：

1. 几何公式成立，逻辑视口完整覆盖实际显示区域，没有二次缩放或非预期裁切。
2. 顶部和底部控件跟随相应边界，居中内容位于指定区域中心；扩展区域按所选布局使用。
3. 关键内容和交互区域可见，点击、拖动与视觉位置一致。
4. 连续 resize、方向变化及高像素密度下行为稳定，业务状态不被适配过程重置。

数学检查不能替代引擎内的布局与输入验证。优先复用已有预览和检查入口，选择足以验证当前变化的检查范围。

## 可选数学示例

仅用于说明几何关系，设计尺寸 `720×1280` 不是默认要求：

| 显示区域 | 缩放率 | 逻辑视口 |
| --- | --- | --- |
| `720×1280` | `1` | `720×1280` |
| `720×1600` | `1` | `720×1600` |
| `1440×900` | `0.703125` | `2048×1280` |

这些结果应与引擎最终坐标和布局范围一致，而不仅仅是单独的计算函数返回值。
