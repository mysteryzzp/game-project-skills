# 对业务透明的自动图集

接入合图、修改图片加载链路或排查开发与发布资源差异时读取。稳定资源标识、构建映射和引擎加载共同构成本模块，不拆成互不关联的功能。

## 必须保持的行为

- 源码资源目录保留原始碎图，打包不移动、重命名或覆盖源素材。
- 开发运行直接使用碎图；发布时按项目规则自动合图，未合图图片仍可正常加载。
- 业务使用同一图片标识和加载调用，不填写图集名、帧坐标，也不分支判断开发或发布模式。
- 同一标识返回业务可使用的图片、纹理或 Sprite 资源，合图后保持原始显示尺寸及透明边缘的定位语义。
- 资源映射和生成物随构建更新，正式运行不读取开发机器路径、Skill 目录或临时构建目录。

业务只知道稳定标识及项目公开的加载接口；构建层和加载层可以知道图集。安装 Skill 或只写映射表，并不会让现有图片 API 自动支持图集。

## 先选择引擎接入方式

检查引擎原生自动图集、资源 GUID、Sprite 导入和发布管线。如果原生机制同时满足开发碎图、发布合图、业务引用不变，优先采用它，不额外实现资源管理器。

原生能力不能满足目标时，将共享合图构建流程与引擎加载接入分开实现。合图工具可以沿用同一款，但元数据导出格式和加载 API 按目标引擎调整。

可以选用支持目标格式的现有打包器；JS 工具链的参考选择是 AssetPack。使用前确认项目所选版本的真实 API 和输出格式，不把案例中的 API、Vite 虚拟模块或依赖版本当成跨引擎标准。

## 图片标识与加载契约

沿用引擎已有的资源标识、GUID 或项目路径；只有现有方式无法支持透明切换时，才补充稳定键与解析入口。无需为此更换全部业务资源命名。

自定义映射可以表达为下列语义，字段名和文件格式由项目决定：

```text
图片标识 -> 独立图片 URL / 引擎资源标识
        或 图集标识 + 帧标识
```

同一调用在开发解析到第一种，发布时可能解析到第二种。不要要求业务先请求图集再请求帧。若业务原来直接加载文件，首次接入时可以统一迁移到透明入口；之后两种构建模式不能再切换业务写法。

从路径生成标识时，明确资源根目录、命名空间、路径分隔符、大小写与扩展名规则。重复 basename 不能互相覆盖；目录改名等源码标识变化与构建哈希变化应区分。重复标识必须在构建时报告。

## 合图分组与配置

优先沿用项目现有或引擎原生的分组规则。按加载时机、资源生命周期和纹理设置分组；不要为了凑满纹理把互不相关场景放到同一页，也不要合并采样、颜色空间等设置不兼容的资源。

没有既有规则、且选用目录配置时，可以采用以下完整约定作为起点：

- 资源目录可放 `atlas.autoatlas`，JSON 对象配置本目录及其子目录的图片。
- 子目录有配置时，子目录图片归子组，不重复进入父组；查找限定在资源根目录内。
- 无匹配配置的图片保持碎图；空组跳过并提示。
- 每份配置从项目默认参数起步，缺省字段不继承父配置；如项目已有明确继承规则则沿用并说明。
- 容量不足时允许拆为多页，业务标识不变。

可选初始参数：`maxSize: 2048`、`padding: 2`、`allowRotation: false`、`allowTrim: true`。这些值必须结合目标硬件、过滤方式、渲染缩放和引擎能力选择，不是普适的正确默认值。

只有引擎加载接入完整支持旋转帧时才启用旋转；只有能够保留裁剪前尺寸和偏移时才启用透明裁剪。需要 mipmap 或线性过滤时，按采样行为配置 padding/extrude，不能仅凭有间距就认定不会串色。

配置解析检查类型、未知字段和非法范围，出错指出文件与原因。示例约定在采用前应落成项目真正的实现和简短说明，不能只创建一个不会被任何工具读取的配置文件。

## 构建流程

1. 扫描选定资源根目录，生成唯一稳定标识和分组列表。顺序稳定，不依赖临时目录中的历史文件。
2. 开发模式生成碎图映射，接入开发服务器或引擎导入机制；图片新增、删除、修改后映射和预览能正确更新。
3. 发布模式将源素材副本或只读输入交给打包器，产物写入专用生成目录。清理仅覆盖已核实属于该任务的生成路径。
4. 检查每张分组源图片恰好映射到一个输出帧，拒绝遗漏、重复或意外帧；记录拆页后的真实归属。
5. 将图集页、帧元数据和未合图图片接入实际构建依赖。由工具链处理最终 URL、哈希和部署基路径，而不是运行时拼接源文件名。
6. 将输出映射交给引擎加载层，发布包不依赖打包器元数据里未经处理的本机路径或原始图片相对路径。

图集元数据可以作为构建模块，也可以作为发布资源，但必须被打包、加载并正确解析关联图片。是否将未使用资源移除或提供生产碎图对照模式，依据项目实际需求选择，不自动扩大发布改造范围。

## 引擎加载接入

加载层根据标识解析独立图片或图集帧，并返回该引擎已有业务接口所期望的资源类型。集中处理这些细节：

- 合并同一图片和同一图集页的并发加载与解析；失败后允许重试，避免永久缓存失败 Promise。
- 正确处理裁剪前尺寸、偏移、旋转和枢轴，防止开发与发布布局或点击范围变化。
- 使用引擎常规资源缓存，避免全局帧别名发生冲突。加载某帧通常会带入整页资源，分组和预加载范围应匹配。
- 资源卸载与引用计数沿用项目策略。销毁一个 Sprite 不等于可以销毁仍被其他对象使用的整页纹理；不默认把所有纹理留到会话结束。

薄层接入即可满足时，不强制新建完整资源框架。PNG 图标只是普通源素材，不需要另一套图集协议。

## 验证

使用同一业务代码分别运行开发碎图和发布合图，确认不是只验证了构建成功：

- 同一标识可加载，图片尺寸、透明留白、位置和交互区域一致。
- 嵌套目录和不同目录的同名图片正确，分组边界和未合图图片均有效。
- 使用到的裁剪、旋转和多页行为在引擎内真实有效；未采用的能力不必额外实现。
- 并发加载共用图集，失败可以重试；项目有卸载机制时验证共享纹理不会提前销毁。
- 源图片未被构建修改，新增或删除图片后无陈旧映射或旧帧残留。
- 真实发布目录在项目部署基路径下可用，运行不访问源码或临时路径。

尽量复用现有浏览器、引擎预览或资源检查工具。缺少引擎运行环境时，明确哪些只完成静态或构建验证，不将其描述成已验证运行时透明性。
