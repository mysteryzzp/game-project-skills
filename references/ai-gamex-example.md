# ai-gamex 参考案例

仅在需要具体组合案例时读取。以下内容来自已有项目的只读检查，作为设计说明保存在 Skill 内；使用 Skill 不需要检出或读取原项目。本文件不是独立可运行的引擎适配器。

## 项目背景

Web 小游戏合集，使用 TypeScript、PixiJS 8、`@pixi/layout` 和 Vite。以下路径是参考项目中的相对路径示意，不是新项目必须采用的结构。

## Expand

- `src/core/viewport.ts` 用设计尺寸 `720×1280` 计算统一缩放和实际逻辑视口。
- `src/app/bootstrap.ts` 建立缩放根节点与布局根节点，窗口变化后更新视口并通知场景。
- 子场景用逻辑尺寸布局，不重复乘缩放率；DPR 用于渲染清晰度。
- 项目中的多尺寸布局检查覆盖长屏、桌面和横屏，并验证顶部、底部、居中区域与内容边界。

可复用的是几何关系、布局边界与验证思路。根节点结构、左上原点、DPR 上限和具体布局库都是该项目的选择。

## 图标

- `icons.config.json` 将项目图标名称映射到 Phosphor 图标名，可指定输出尺寸和颜色。
- `scripts/generate-icons.mjs` 从本地 Iconify 集合取 SVG，用 Sharp 生成透明 PNG，写入 `src/assets/shared/icons/`。
- `icons:generate` 显式生成，`icons:check` 检查配置与输出是否一致。配置和 PNG 一起提交，开发服务器不自动生成。
- 生成清单区分自动生成图片和手工素材，移除配置项时避免误删手工图片。
- 该项目使用白色图标和运行时染色，属于单色方案，不应用于需要保留多色或渐变的新项目。

可复用的是“选取源图标—记录参数—生成本地 PNG—用项目资源系统加载”的链路，不是 Phosphor 或白色限制。

## 透明图集

- `atlas-plugin.ts` 扫描公共和各游戏资源目录，产生稳定逻辑名称。
- 开发模式保留碎图映射；发布模式读取 `atlas.autoatlas`，用 AssetPack 按目录配置合图。
- 最近的目录配置决定分组，子配置参数从默认值起步，不继承父参数。没有配置的图片保持碎图，容量不足时可拆页。
- 打包使用专用临时目录和源素材副本，不改写源 PNG。
- 插件生成 Vite 虚拟模块，将图片和元数据接入构建依赖，让 Vite 处理内容哈希和基路径。
- `src/core/resources.ts` 按同一逻辑名称返回 PixiJS Texture，内部区分单图与图集帧，复用并发请求和图集解析。
- 业务场景无需知道图集名或帧位置。

可复用的是稳定标识、按规则合图、构建映射与加载接入的分工。Vite 虚拟模块和 PixiJS 的 Spritesheet API 都需要按新项目重新判断。

如果在相同工具链中参考这条路线，构建插件、虚拟模块声明、加载器与构建配置必须协调接入，不能仅复制加载器就假定图集已经透明可用。

## 不自动推广的选择

以下内容不是三个模块的普遍要求：

- 普通图片一律允许变形填满，不提供 contain/cover。
- 所有 UI 必须由 PixiJS 绘制，必须使用 `@pixi/layout`。
- 图标必须白色、必须使用 Phosphor。
- 必须采用特定游戏目录结构、构建命令或相同设计尺寸。

案例只记录设计与已存在的检查入口，本次 Skill 提炼未重新执行参考项目的运行时测试，不代表已验证其他引擎。
